# Решение ошибки 502 на Railway

## Проблема
Ошибка 502 при загрузке `main.jsx` означает, что Vite dev server не запускается или не может обслуживать статические файлы.

## Диагностика

### Шаг 1: Проверьте логи Railway

Откройте Railway Dashboard → Deployments → View Logs

**Что должно быть в логах:**

1. **Логи SERVER:**
   ```
   [SERVER] 🚀 Начало инициализации сервера...
   💾 Инициализация базы данных...
   ✅ База данных инициализирована успешно
   🚀 Сервер запущен на порту 3000
   ```

2. **Логи FRONTEND:**
   ```
   [FRONTEND] ⏳ Ожидание готовности сервера на порту 3000
   [FRONTEND] ✅ Сервер готов! Запускаем Vite...
   [FRONTEND] 🚀 Запуск Vite dev server...
   VITE v5.x.x  ready in xxx ms
   ```

### Шаг 2: Проверьте переменные окружения

В Railway Dashboard → Settings → Variables:

- ✅ `SERVER_PORT=3000` - **ОБЯЗАТЕЛЬНО**
- ❌ `VITE_API_BASE_URL` - **НЕ должно быть** (удалите, если есть)

### Шаг 3: Проверьте health endpoint

Откройте в браузере:
```
https://your-app.railway.app/health
```

Если health endpoint не отвечает - сервер не запущен.

## Решения

### Решение 1: Если Vite не запускается

Если в логах FRONTEND нет сообщения "VITE v5.x.x ready", значит Vite не запускается.

**Проверьте:**
1. Есть ли ошибки в логах FRONTEND?
2. Установлены ли все зависимости? (`npm install`)
3. Правильная ли версия Node.js? (>= 20.0.0)

### Решение 2: Если скрипт wait-and-start-vite.js не работает

Если в логах FRONTEND нет сообщения "[FRONTEND] ⏳ Ожидание готовности сервера", значит скрипт не запускается.

**Попробуйте упрощенный вариант:**

Измените `package.json`:
```json
"start": "echo '🚀 Запуск приложения...' && concurrently --restart-tries 3 --restart-after 2000 --names \"SERVER,FRONTEND\" --prefix-colors \"blue,green\" --prefix \"[{name}]\" \"npm run server\" \"sleep 5 && npm run dev\"",
```

**ВНИМАНИЕ:** На Railway (Linux) команда `sleep` должна работать.

### Решение 3: Если сервер не запускается

Если в логах SERVER нет сообщения "🚀 Сервер запущен на порту 3000", значит сервер не запускается.

**Проверьте:**
1. Есть ли ошибки в логах SERVER?
2. Установлена ли переменная `SERVER_PORT=3000`?
3. Есть ли проблемы с инициализацией БД?

### Решение 4: Откат к рабочей версии

Если два коммита назад все работало:

1. Найдите рабочий коммит в Git
2. Посмотрите, что изменилось в `package.json`
3. Откатите изменения или примените только необходимые исправления

**Команды:**
```bash
git log --oneline -10  # Посмотреть последние коммиты
git show <commit-hash>  # Посмотреть изменения в коммите
git checkout <commit-hash> -- package.json  # Откатить package.json
```

## Быстрое исправление

Если нужно быстро исправить, попробуйте самый простой вариант:

```json
"start": "echo '🚀 Запуск приложения...' && concurrently --restart-tries 3 --restart-after 2000 --names \"SERVER,FRONTEND\" --prefix-colors \"blue,green\" --prefix \"[{name}]\" \"npm run server\" \"npm run dev\"",
```

Это запустит оба процесса одновременно без задержки. Если сервер запускается быстро, это должно работать.

## Проверка после исправления

1. Перезапустите деплой на Railway
2. Проверьте логи - должны быть оба процесса (SERVER и FRONTEND)
3. Проверьте health endpoint - должен отвечать
4. Откройте приложение - должно загружаться без ошибок 502

## Если ничего не помогает

1. **Проверьте логи полностью** - скопируйте все логи и ищите ошибки
2. **Проверьте файлы** - убедитесь, что все файлы закоммичены
3. **Проверьте переменные окружения** - убедитесь, что все правильно
4. **Свяжитесь с поддержкой Railway** - приложите логи и описание проблемы
