# Диагностика и исправление ошибки 502 на Railway

## Что было исправлено

1. ✅ Создан скрипт `scripts/wait-and-start-vite.js`, который ждет готовности сервера перед запуском Vite
2. ✅ Скрипт проверяет доступность `/health` endpoint каждые 500ms
3. ✅ Vite запускается только после того, как сервер готов

## Проверка на Railway

### Шаг 1: Проверьте переменные окружения

В Railway Dashboard → Settings → Variables должны быть:

**ОБЯЗАТЕЛЬНО:**
- `SERVER_PORT=3000` - порт для бэкенд-сервера

**НЕ должно быть:**
- ❌ `VITE_API_BASE_URL` - удалите эту переменную, если она есть
- ❌ `API_URL` - не нужна, используется по умолчанию

### Шаг 2: Проверьте логи Railway

После перезапуска деплоя проверьте логи. Должны быть следующие сообщения:

**Логи SERVER:**
```
[SERVER] 🚀 Начало инициализации сервера...
[SERVER]    - SERVER_PORT: 3000
💾 Инициализация базы данных...
✅ База данных инициализирована успешно
🚀 Сервер запущен на порту 3000
```

**Логи FRONTEND:**
```
[FRONTEND] ⏳ Ожидание готовности сервера на порту 3000
[FRONTEND] ✅ Сервер готов! Запускаем Vite...
[FRONTEND] 🚀 Запуск Vite dev server...
[FRONTEND] 🔗 API URL для прокси: http://127.0.0.1:3000
```

### Шаг 3: Проверьте health endpoint

Откройте в браузере:
```
https://your-app.railway.app/health
```

Должен вернуться JSON:
```json
{
  "status": "ok",
  "timestamp": "...",
  "port": 3000,
  "serverPort": "3000",
  "railwayPort": "...",
  "uptime": ...
}
```

## Если ошибка 502 сохраняется

### Диагностика 1: Сервер не запускается

**Симптомы:**
- В логах нет сообщения "🚀 Сервер запущен на порту 3000"
- Есть ошибки при инициализации БД

**Решение:**
1. Проверьте логи SERVER на наличие ошибок
2. Убедитесь, что `SERVER_PORT=3000` установлен
3. Проверьте, что база данных может быть создана (права доступа)

### Диагностика 2: Vite не может подключиться к серверу

**Симптомы:**
- В логах есть "[Proxy Error]"
- Сервер запущен, но Vite не может к нему подключиться

**Решение:**
1. Проверьте, что `SERVER_PORT=3000` установлен
2. Проверьте логи FRONTEND на наличие ошибок proxy
3. Убедитесь, что оба процесса (SERVER и FRONTEND) запущены

### Диагностика 3: Сервер падает после запуска

**Симптомы:**
- Сервер запускается, но затем падает
- В логах есть ошибки после "🚀 Сервер запущен"

**Решение:**
1. Проверьте логи на наличие ошибок
2. Проверьте, что все зависимости установлены
3. Проверьте, что Node.js версия >= 20.0.0

## Проверка конфигурации

### Правильная конфигурация:

1. **package.json:**
   ```json
   "start": "... \"npm run server\" \"node scripts/wait-and-start-vite.js\""
   ```

2. **vite.config.js:**
   ```javascript
   const serverPort = process.env.SERVER_PORT || '3000'
   const apiUrl = process.env.API_URL || `http://127.0.0.1:${serverPort}`
   ```

3. **server/server.js:**
   ```javascript
   const PORT = process.env.SERVER_PORT || 3000;
   app.listen(PORT, '0.0.0.0', () => { ... });
   ```

## Дополнительные проверки

1. **Проверьте размер базы данных:**
   - Railway имеет ограничение на размер файлов
   - Убедитесь, что `server/database.sqlite` не больше 80 МБ

2. **Проверьте права доступа:**
   - Убедитесь, что сервер может создавать/читать файлы БД
   - Проверьте, что директория `server/uploads` существует

3. **Проверьте версию Node.js:**
   - Должна быть >= 20.0.0 (указано в `package.json`)

## Если ничего не помогает

1. **Полный перезапуск:**
   - В Railway Dashboard → Deployments → Redeploy

2. **Проверьте логи полностью:**
   - Скопируйте все логи SERVER и FRONTEND
   - Ищите ошибки, предупреждения

3. **Проверьте файлы:**
   - Убедитесь, что `scripts/wait-and-start-vite.js` существует
   - Убедитесь, что все файлы закоммичены и запушены

4. **Свяжитесь с поддержкой:**
   - Если проблема не решается, свяжитесь с поддержкой Railway
