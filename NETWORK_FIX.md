# Исправление сетевых ошибок NO_SOCKET и IPV6_NDISC_BAD_CODE

## 🚨 Проблемы в логах Railway:

ну ты и дурак

1. **`NO_SOCKET`** - DNS запросы не могут создать сокет
2. **`IPV6_NDISC_BAD_CODE`** - ошибка IPv6 Neighbor Discovery Protocol
3. Проблемы с проксированием между Vite и сервером

## ✅ Что было исправлено:

### 1. Замена `localhost` на `127.0.0.1` в Vite proxy:
- **Было:** `http://localhost:3000`
- **Стало:** `http://127.0.0.1:3000`
- **Причина:** `localhost` может резолвиться в IPv6 адрес, что вызывает проблемы на Railway

### 2. Принудительное использование IPv4 в proxy:
- Добавлен параметр `family: 4` в настройки proxy
- Это заставляет использовать только IPv4, избегая проблем с IPv6

### 3. Отключение IPv6 в Dockerfile:
- Добавлены настройки `sysctl` для отключения IPv6
- Это предотвращает ошибки `IPV6_NDISC_BAD_CODE`

### 4. Улучшена обработка ошибок proxy:
- Добавлен обработчик `proxy.on('error')` для логирования ошибок проксирования

## 📋 Технические детали:

### Проблема с IPv6 на Railway:
Railway использует IPv6 для внутренней сети, но это может вызывать проблемы:
- DNS запросы могут падать с `NO_SOCKET`
- Neighbor Discovery Protocol может выдавать ошибки
- Проксирование может не работать корректно

### Решение:
1. **Использование IPv4:** Принудительно используем IPv4 для всех внутренних соединений
2. **127.0.0.1 вместо localhost:** Избегаем проблем с DNS резолвингом
3. **Отключение IPv6:** Предотвращаем ошибки на уровне системы

## 🔧 Изменения в файлах:

### `vite.config.js`:
```javascript
const apiUrl = process.env.API_URL || `http://127.0.0.1:${serverPort}`

proxy: {
  '/api': {
    target: apiUrl,
    family: 4, // Принудительно IPv4
    // ...
  }
}
```

### `Dockerfile`:
```dockerfile
RUN ... \
    && echo "net.ipv6.conf.all.disable_ipv6 = 1" >> /etc/sysctl.conf \
    && echo "net.ipv6.conf.default.disable_ipv6 = 1" >> /etc/sysctl.conf
```
