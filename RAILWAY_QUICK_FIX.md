# Быстрое исправление ошибки 502 на Railway

## Проблема
Ошибка 502 при загрузке `main.jsx` и других статических файлов означает, что Vite dev server не запускается или не может обслуживать файлы.

## Возможные причины

1. **Скрипт wait-and-start-vite.js не работает** - возможно, есть ошибки в скрипте
2. **Сервер не запускается** - возможно, есть ошибки при инициализации
3. **Проблемы с портами** - возможно, порты конфликтуют

## Быстрое решение

### Вариант 1: Упрощенный запуск (рекомендуется)

Измените `package.json`:

```json
"start": "echo '🚀 Запуск приложения...' && concurrently --restart-tries 3 --restart-after 2000 --names \"SERVER,FRONTEND\" --prefix-colors \"blue,green\" --prefix \"[{name}]\" \"npm run server\" \"sleep 5 && npm run dev\"",
```

**ВНИМАНИЕ:** На Railway (Linux) команда `sleep` должна работать. Если не работает, используйте Вариант 2.

### Вариант 2: Без задержки (если сервер запускается быстро)

```json
"start": "echo '🚀 Запуск приложения...' && concurrently --restart-tries 3 --restart-after 2000 --names \"SERVER,FRONTEND\" --prefix-colors \"blue,green\" --prefix \"[{name}]\" \"npm run server\" \"npm run dev\"",
```

## Проверка логов Railway

После изменения проверьте логи:

1. **Должны быть логи SERVER:**
   ```
   [SERVER] 🚀 Начало инициализации сервера...
   🚀 Сервер запущен на порту 3000
   ```

2. **Должны быть логи FRONTEND:**
   ```
   [FRONTEND] 🚀 Инициализация Vite...
   VITE v5.x.x  ready in xxx ms
   ```

3. **Если Vite не запускается:**
   - Проверьте, что нет ошибок в логах FRONTEND
   - Проверьте, что все зависимости установлены
   - Проверьте, что Node.js версия >= 20.0.0

## Если проблема сохраняется

### Шаг 1: Проверьте переменные окружения

В Railway Dashboard → Settings → Variables:

- ✅ `SERVER_PORT=3000` - должно быть установлено
- ❌ `VITE_API_BASE_URL` - НЕ должно быть (удалите, если есть)

### Шаг 2: Проверьте логи полностью

Скопируйте все логи SERVER и FRONTEND и проверьте на наличие ошибок:

- Ошибки при инициализации БД
- Ошибки при запуске сервера
- Ошибки при запуске Vite
- Ошибки proxy

### Шаг 3: Проверьте health endpoint

Откройте в браузере:
```
https://your-app.railway.app/health
```

Если health endpoint не отвечает, сервер не запущен.

### Шаг 4: Откатитесь к рабочей версии

Если два коммита назад все работало:

1. Найдите рабочий коммит
2. Посмотрите, что изменилось в `package.json` и `vite.config.js`
3. Откатите изменения или примените только необходимые исправления

## Диагностика

### Проверка 1: Сервер запущен?

```bash
# В логах Railway должно быть:
🚀 Сервер запущен на порту 3000
```

Если нет - проверьте ошибки в логах SERVER.

### Проверка 2: Vite запущен?

```bash
# В логах Railway должно быть:
VITE v5.x.x  ready in xxx ms
```

Если нет - проверьте ошибки в логах FRONTEND.

### Проверка 3: Proxy работает?

Откройте DevTools → Network и проверьте запросы к `/api/*`:
- Если запросы идут на `/api/*` - хорошо
- Если запросы идут на `localhost:3000` - проблема в переменных окружения

## Рекомендации

1. **Используйте простой подход** - не усложняйте скрипты запуска
2. **Проверяйте логи** - они покажут, где именно проблема
3. **Тестируйте локально** - убедитесь, что `npm start` работает локально
4. **Используйте health endpoint** - для проверки готовности сервера
