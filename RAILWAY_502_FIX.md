# Исправление ошибки 502 Bad Gateway на Railway

## Проблема
После деплоя на Railway возникают ошибки:
- `502 Bad Gateway`
- `Failed to load resource: the server responded with a status of 502`

## Причина
Ошибка 502 означает, что Vite proxy не может подключиться к бэкенд-серверу. Это может происходить по нескольким причинам:
1. Сервер не успевает запуститься до того, как Vite начинает делать запросы
2. Проблемы с инициализацией базы данных
3. Неправильная конфигурация портов
4. Сервер падает при запуске из-за ошибки

## Что было исправлено

### 1. Улучшена обработка ошибок при запуске сервера
- Добавлена обработка ошибок при запуске сервера (EADDRINUSE и другие)
- Улучшена обработка ошибок инициализации базы данных
- Сервер теперь логирует подробные ошибки для диагностики

### 2. Улучшена конфигурация Vite proxy
- Добавлены таймауты (30 секунд для API, 5 секунд для health check)
- Улучшена обработка ошибок proxy с понятными сообщениями
- Добавлено логирование успешных и неуспешных запросов

### 3. Добавлена задержка перед запуском Vite
- Vite теперь запускается с задержкой 3 секунды после сервера
- Это дает серверу время для инициализации БД и запуска

## Настройка на Railway

### Обязательные переменные окружения:
- `SERVER_PORT=3000` - порт для бэкенд-сервера (ОБЯЗАТЕЛЬНО!)

### Проверка логов Railway

После деплоя проверьте логи в Railway Dashboard. Вы должны увидеть:

**Логи SERVER:**
```
[SERVER] 🚀 Начало инициализации сервера...
[SERVER]    - SERVER_PORT: 3000
💾 Инициализация базы данных...
✅ База данных инициализирована успешно
🚀 Сервер запущен на порту 3000
```

**Логи FRONTEND:**
```
[FRONTEND] 🚀 Инициализация Vite...
[FRONTEND]    - PORT: <порт от Railway>
[FRONTEND]    - SERVER_PORT: 3000
[FRONTEND] 🔗 API URL для прокси: http://127.0.0.1:3000
```

### Если ошибка 502 сохраняется:

1. **Проверьте, что SERVER_PORT установлен:**
   - В Railway Dashboard → Settings → Variables
   - Должна быть переменная `SERVER_PORT=3000`

2. **Проверьте логи SERVER:**
   - Если сервер не запускается, проверьте ошибки в логах
   - Убедитесь, что база данных инициализируется успешно

3. **Проверьте логи FRONTEND:**
   - Если видите ошибки proxy, проверьте, что API URL правильный
   - Должно быть: `http://127.0.0.1:3000`

4. **Проверьте, что оба процесса запущены:**
   - В логах должны быть и SERVER, и FRONTEND процессы
   - Если один из них упал, concurrently попытается перезапустить его

5. **Проверьте health endpoint:**
   - Откройте `https://your-app.railway.app/health` в браузере
   - Должен вернуться JSON с информацией о сервере

## Дополнительная диагностика

Если проблема сохраняется, проверьте:

1. **Размер базы данных:**
   - Railway имеет ограничение на размер файлов
   - Убедитесь, что `server/database.sqlite` не больше 80 МБ

2. **Права доступа:**
   - Убедитесь, что сервер может создавать/читать файлы БД
   - Проверьте, что директория `server/uploads` существует

3. **Порты:**
   - Убедитесь, что `SERVER_PORT=3000` установлен
   - Не устанавливайте `PORT` вручную (Railway делает это автоматически)

## Если ничего не помогает

1. Перезапустите деплой на Railway
2. Проверьте, что все зависимости установлены (`npm install` выполнен)
3. Проверьте, что Node.js версия >= 20.0.0 (указано в `package.json`)
4. Свяжитесь с поддержкой Railway, если проблема не решается
