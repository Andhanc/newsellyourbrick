ТЗ: внедрение AI-маркетинга на SellYourBrick
Дата: 2026-07-15
Источник идей: marketing.txt (воронка property → content → publish → leads → CRM → report)
Статус: общее продуктово-техническое ТЗ (roadmap), не детальные тикеты разработки

================================================================================
1. ЦЕЛЬ
================================================================================

Построить на SellYourBrick автоматизированный маркетинг-конвейер вокруг объектов
на платформе: из каждого (или выбранного) листинга система готовит контент,
публикует/предлагает к публикации, помогает ловить и прогревать лиды, обновляет
CRM и показывает, какие каналы дают клиентов.

Бизнес-эффект:
- больше маркетингового выхода без отдельной контент-команды;
- sales тратит время на закрытие сделок, а не на ручное написание постов
  и «догон» холодных лидов;
- единый цикл: объект → контент → канал → лид → встреча → отчёт.

Важно: объекты на платформе уже есть (в т.ч. можно выгрузить/использовать
существующие). Узкое место — не наполнение каталога, а связка «approve /
выбранный объект → маркетинг-пайплайн» и дальнейшая автоматизация каналов.

Целевая картина (из исходного списка, адаптировано под SYB):
1) Новый / выбранный property
2) AI пишет статью
3) AI делает пакет соцпостов (до ~20)
4) AI готовит видео-скрипты / заготовки роликов
5) Email-кампания / nurture
6) Публикация по каналам
7) Обновление сайта
8) Индексация / SEO
9) Реклама
10) Ответы на заявки
11) Бронирование встреч / test-drive
12) Обновление CRM
13) Follow-up клиента
14) Отчёт по результатам

Принцип: Minimal human involvement — но с контрольными точками модерации
на брендовых публикациях (см. раздел «Роли человека»).


================================================================================
2. SCOPE
================================================================================

2.1. Берём СЕЙЧАС (MVP — опора на уже существующее в продукте)
-------------------------------------------------------------------
Уже есть в SYB (использовать, не изобретать заново):
- объекты / модерация / approve → публичный листинг;
- перевод карточек объектов (property_translations);
- SEO: sitemap, SSR/meta, JSON-LD, админ SEO-панель;
- AI-генерация новостей в Marketer Panel (пока не привязана к property);
- on-site рекламные блоки (site ads) в маркетологе;
- CRM (канбан, лиды, активности), Smart Assistant / live chat;
- EmailJS (транзакционные / CRM-письма, не маркетинговые кампании);
- test-drive бронирования;
- UI i18n (ru, en, de, es, fr, sv, pl).

MVP scope:
- Триггер пайплайна: property.approved (и/или ручной «запустить маркетинг»
  по существующему объекту из админки / marketer).
- AI-черновик новости / статьи из полей объекта (переиспользовать news AI;
  сейчас генерация не привязана к property_id — это и есть основная доработка).
- Черновик «пакета постов» (тексты; публикация вручную или через оркестратор позже).
- Включить в job перевод карточки (сейчас translate чаще ручной/по запросу)
  + опора на уже работающий sitemap/SSR после approve.
- Уведомление sales / запись активности в CRM при запуске пайплайна
  или при входящем лиде с UTM/источником «marketing».
- Тонкий outbound webhook (property.approved, news.published, lead.created)
  для будущей связки с n8n/Make — без обязательного HubSpot в MVP.
- Модерация публикации: человек утверждает статью/посты до «в эфир».
- Карточка объекта на сайте уже появляется после approve — в MVP «обновление
  сайта» для маркетинга = публикация новости/пакета, не повторный listing.

2.2. Берём ПОТОМ (v2)
-------------------------------------------------------------------
- Мультиязычные статьи/новости (сейчас генерация по сути RU-centric).
- Перенос news/site-ads с JSON-файлов на устойчивое хранилище (БД),
  если масштабируем маркетинг-команду / несколько инстансов.
- Email-последовательности (ESP: Brevo / Resend и т.п.) вместо только EmailJS.
- Соцпостинг через n8n/Make + API Meta / LinkedIn / X / Telegram
  (или Buffer/аналог) + планировщик.
- IndexNow / ping Search Console после публикации URL.
- WhatsApp template follow-up (расширение уже существующих WhatsApp-паттернов
  в проекте для auction reminders и т.п.).
- Видео: скрипт + storyboard + (опционально) генерация/сборка коротких роликов;
  полная авто-публикация видео — после пилота качества.

2.3. Берём ДАЛЬШЕ (v3 / целевой AI-экосистема)
-------------------------------------------------------------------
- Полноценный оркестратор (n8n / Make / Zapier) как «шина» процессов.
- Платные ads API (Google / Meta / TikTok) + бюджетные правила.
- AI-агент 24/7 по объектам, инвестициям и процессу покупки
  (усиление текущего assistant / property AI).
- AI lead scoring (расширение hot/warm/cold) + приоритизация sales.
- Дашборд «какой канал даёт самых ценных клиентов» (атрибуция UTM/ROAS).
- Опционально внешний marketing CRM (HubSpot / GoHighLevel), если внутреннего
  CRM станет мало; до этого — доращиваем свой CRM + webhook.

2.4. НЕ берём (осознанно out of scope / не обещаем «включено»)
-------------------------------------------------------------------
- Полностью безлюдная публикация во все каналы без модерации бренда (в MVP/v2).
- «Магия» индексации Google без sitemap/SSR + времени на crawl
  (автопинг — v2, гарантий позиции нет).
- Замена sales людей на AI closing сделок.
- Мгновенный паритет с фантазийным кейсом «House Tenerife as if built today»
  одной итерацией — это целевая архитектура, не один спринт.


================================================================================
3. ЭТАПЫ
================================================================================

Общий принцип: roadmap содержит ВСЮ воронку из marketing.txt, но внедряем
по фазам. Объекты уже есть → стартуем с автоматизации вокруг approve и
массового «запустить маркетинг» по выгрузке/выборке.

----- Фаза 0. Подготовка (коротко) -----
- Зафиксировать event-модель: property.approved, marketing.job.requested,
  news.draft.ready, news.published, lead.created, meeting.booked.
- Инвентаризация каналов (сайт, Instagram/TikTok/Telegram и т.д.) и доступов.
- Выбор оркестратора на перспективу (рекомендация: n8n self-host или Make).
- Выбор LLM-провайдера (уже есть AI_PROVIDER / OpenRouter и др. — унифицировать
  для news + social + email копирайта).

----- Фаза 1. MVP: «объект → контент → сайт → CRM-сигнал» -----
Приоритет: высокий. Даёт видимый маркетинговый выход на существующих объектах.

1.1. Хук после approve (и кнопка «Generate marketing pack» для уже approved).
1.2. AI: статья/новость из данных объекта → черновик в Marketer Panel.
1.3. AI: пакет текстов соцпостов (N шт., конфигурируемо; цель до 20) → черновики.
1.4. Человек: правки → Publish новости; посты копирует/постит вручную или
     экспортирует CSV/в оркестратор.
1.5. SEO: опираемся на текущий sitemap/SSR; опционально ручной refresh sitemap.
1.6. CRM/sales: уведомление «новый маркетинговый пакет / новый лид».
1.7. Webhook наружу для n8n (даже если workflow ещё пустой).

Критерий готовности MVP:
- для выбранного approved-объекта за ~5–15 минут (зависит от LLM) появляются
  черновики статьи и постов; новость можно опубликовать на сайте; sales видит
  сигнал в CRM или email.
- пилот: минимум 2 объекта «с нуля» + 5 объектов из уже существующего каталога.

----- Фаза 2. «Каналы и follow-up» -----
Приоритет: средний–высокий после стабилизации качества контента.

2.1. n8n/Make: публикация постов по расписанию после approve маркетолога.
2.2. Email nurture / анонсы новых объектов (ESP).
2.3. IndexNow / notify URL.
2.4. WhatsApp/email follow-up до бронирования встречи / test-drive.
2.5. Видео: генерация скриптов + шаблон short-form; пилот 1–2 канала.
2.6. Мультиязычность контент-паков под ключевые lang UI.

Критерий готовности v2:
- один объект → сайт + ≥1 соцсеть + email-цепочка без ручного копипаста;
- входящий лид получает авто-серию до meeting booked или эскалации человеку.

----- Фаза 3. «Реклама, scoring, отчёты, агент» -----
Приоритет: после измеримого органического контура.

3.1. Запуск/управление ads (или полуавтомат через оркестратор + ручные бюджеты).
3.2. AI-ответы на типовые inquiry с эскалацией менеджеру.
3.3. Lead scoring + очередь для sales.
3.4. Дашборд каналов (UTM, лиды, встречи, сделки / ценность).
3.5. Усиление AI-агента «знание всех объектов + процесс покупки».

Критерий готовности v3:
- отчёт «канал → квалифицированный лид → встреча → сделка»;
- ручная работа сосредоточена на модерации бренда и closing.

4. ИНТЕГРАЦИИ
================================================================================

4.1. Внутренние системы SYB (обязательная база)
- Сайт / публичные страницы объектов и новостей
- Админка: модерация объектов, CRM, SEO-панель
- Marketer Panel: новости, site ads, (новые) marketing packs
- Property APIs + bulk/выгрузка существующих объектов
- Translation / multilingual
- Уведомления (in-app / EmailJS на старте)

4.2. AI / LLM
- Текущий стек проекта (OpenRouter / Gemini / Groq и т.п. через AI_PROVIDER)
- На перспективу из списка: OpenAI GPT, Anthropic Claude, Google Gemini,
  Perplexity (research/справочный слой — опционально)

4.3. Оркестрация
- n8n (предпочтительно для self-host контроля) или Make / Zapier
- Вход: webhooks SYB → n8n
- Выход: соцсети, ESP, ads API, Slack/Telegram sales alerts

4.4. CRM
- Фаза 1–2: внутренний CRM SYB (+ активности, температуры)
- Фаза 3 (опционально): HubSpot / GoHighLevel, если нужны marketing automation
  out-of-the-box и sales pipeline на стороне маркетинга

4.5. Каналы дистрибуции
- Сайт (новости, карточки, site ads) — уже
- Соцсети: Instagram / TikTok / Telegram / Facebook / LinkedIn / X — v2
- Email ESP — v2
- WhatsApp Business templates — v2
- Google / Meta Ads — v3

4.6. SEO / индексация
- Существующий sitemap + SSR + JSON-LD — сейчас
- IndexNow / Search Console API — v2


================================================================================
5. ПОТОКИ
================================================================================

5.1. Основной поток (happy path)
[A] Триггер
  - Модератор одобрил объект (pending → approved), ИЛИ
  - Marketer/admin нажал «Создать marketing pack» для существующего объекта
    (в т.ч. после выгрузки/выборки из каталога).

[B] Подготовка данных
  - Собрать: title, location, price, type, описание, фото, slug/URL, sale format.
  - При необходимости догнать переводы карточки.

[C] AI Generation Job
  - Статья/новость (черновик, связь property_id).
  - Пакет соцпостов (tone/length/CTA по шаблону бренда).
  - (v2+) email-письма, видео-скрипт, варианты A/B заголовков.
  - Статус job: queued → generating → draft_ready → needs_review → published
    / rejected.

[D] Human review (Marketer Panel)
  - Правки текстов, выбор обложки (Unsplash/AI cover — как в news сейчас).
  - Approve publish на сайт / schedule соцпостов.

[E] Publish & SEO
  - Новость live на сайте.
  - Карточка объекта уже public после approve.
  - Sitemap включает approved+slug; (v2) ping индексации нового URL.

[F] Distribution (v2+)
  - n8n публикует посты / ставит в очередь.
  - Email-кампания сегменту инвесторов / подписчиков.
  - (v3) запуск или пополнение ads creatives.

[G] Demand capture
  - Лид: Smart Assistant / live chat / форма / WhatsApp / «написать менеджеру».
  - Лид попадает в CRM (+ источник/UTM/property_id).

[H] Follow-up & meeting
  - (v2) автосерия email/WhatsApp до booking.
  - Booking: test-drive / встреча (календарь — эволюция поверх current bookings).
  - Sales обновляет стадии CRM; AI scoring подсказывает приоритет (v3).

[I] Report
  - Сводка по объекту/пакету: просмотры, клики, лиды, встречи, сделки.
  - (v3) сравнение каналов по ценности клиента.

5.2. Поток для уже существующих объектов (ваш кейс «просто выгрузить»)
- Выборка approved объектов (фильтр: город, тип, без marketing pack за 30 дней).
- Bulk «Generate packs» (очередь, rate limit LLM).
- Дальше тот же review → publish, без ожидания нового approve.

5.3. Кто утверждает
- Контент бренда на сайте и в соцсетях: Marketer (обязательно в MVP/v2).
- Бюджет ads: Marketer + владелец бюджета.
- Ответы клиенту / эскалация: Sales; AI только шаблоны и первый контакт
  с явным handoff.


================================================================================
6. РОЛИ ЧЕЛОВЕКА
================================================================================

AI / система:
- Генерация черновиков (статья, посты, позже email/видео-скрипты).
- Переводы, SEO-поля по шаблонам, постановка в очередь.
- (v2+) автопостинг по утверждённому расписанию, drip follow-up.
- (v3) scoring, черновики ответов на inquiry, отчёты.

Marketer / контент:
- Ревью и правка текстов под бренд SellYourBrick.
- Финальный publish / schedule.
- Настройка тона, CTA, запрещённых формулировок.
- Управление site ads и (позже) креативами для платных каналов.

Sales / менеджер:
- Работа с CRM-лидами, живые переговоры, closing.
- Назначение встреч / test-drive, если не забронировано клиентом.
- Обратная связь: «какой контент приводит слабых/сильных лидов».

Admin / продукт:
- Права, модерация объектов, SEO-overrides, доступ Marketer Panel.
- Webhooks, ключи LLM/оркестратора, соответствие GDPR.

Не цель автоматизации на старте:
- подпись договоров, юридические обещания доходности, «окончательные»
  инвестиционные советы без человека.


================================================================================
7. МЕТРИКИ
================================================================================

Операционные (пайплайн):
- % объектов с marketing pack за 7 дней после approve
- время approve → draft_ready
- время draft_ready → published
- доля черновиков, отклонённых marketer (качество AI)

Маркетинговые:
- публикации: новости, посты, email sends
- трафик на URL объекта / новости (по каналу, UTM)
- CTR креативов / постов (где доступно API)

Воронка продаж:
- лиды (всего / с property_id / с UTM)
- квалифицированные лиды (temperature / scoring)
- встречи / test-drive bookings
- конверсия лид → встреча → сделка (если есть в CRM)

Экономика (v3, когда будут ads):
- CAC по каналу
- стоимость лида / стоимость встречи
- ценность клиента / ROAS (по возможности)

Отчётность:
- MVP: простая сводка в админке или экспорт + ручной отчёт marketer
- v3: дашборд «канал → ценность клиента»


================================================================================
8. РИСКИ
================================================================================

Качество контента / бренд:
- AI может галлюцинировать метраж, доходность, юридические условия.
  Митигация: генерация строго из полей объекта + disclaimer + обязательный review.

Репутация:
- автопостинг без ревью → риск. Митигация: human-in-the-loop до конца v2.

GDPR / коммуникации:
- email/WhatsApp только с согласия / по законному основанию; отписка; хранение
  согласий; не светить персональные данные в промптах третьим LLM без политики.

Бюджет ads:
- без атрибуции легко сжечь бюджет. Митигация: ads только после UTM + CRM связки.

Техдолг хранилища:
- news/site-ads на JSON — ок для старта, риск при росте. Митигация: миграция в БД в v2.

Зависимость от внешних API:
- лимиты LLM, блокировки соцAPI, падение ESP. Митигация: очередь, retry,
  ручной fallback export.

Ожидания «minimal human involvement»:
- полное соответствие pitch из marketing.txt — это v3, не MVP.
  Митигация: честно коммуницировать фазы стейкхолдерам.

================================================================================
9. РЕКОМЕНДУЕМЫЙ ПОРЯДОК СТАРТА (практика)
================================================================================

1) Согласовать это ТЗ со стейкхолдерами (что в MVP обязательно).
2) Сделать event + кнопку «marketing pack» на 1–2 пилотных объектах.
3) Довести качество промптов под бренд SYB (статьи + 10–20 постов).
4) Подключить webhook → пустой n8n workflow (задел под соцсети).
5) Только после стабильного publish на сайт — автоматизировать каналы и email.
6) Параллельно наладить UTM + запись источника в CRM (иначе отчёты бесполезны).

Итог: весь список из marketing.txt входит в roadmap SellYourBrick; ближайший
релизуемый срез — автоматизация «существующий/новый объект → AI-черновики
→ сайт + сигнал sales», с человеком на модерации бренда.
